## Фаза 4. Глубже в экосистему Cardano (сб, если фазы 0–3 готовы к ~11:00)
Выбирать одно по времени; порядок = отношение ценности к риску.

### 4A. ✅ Якорь вердикта on-chain (метаданные) — `ANCHOR=true`, тест на моке Blockfrost
- После продажи сервер публикует tx с метаданными (label 674 / свой label): `requestHash`, `keccak(data)`, `signature`, `airnode`.
- Нужен небольшой баланс у продавца (он получает 2 tADA за продажу, этого хватает).
- Результат: любой может найти вердикт в Cardano, а Cardanoscan показывает его как метаданные.

### 4B. ⬜ Masumi: зарегистрировать сервис как агента, ~2 ч, средний риск (нужны публичный HTTPS и ~20 tADA)
- По `x402-cardano-demo/masumi/README.md`: кошелёк продавца ~20 tADA, публичный HTTPS (cloudflared), `npm run register`.
- Плюс: escrow, листинг на Sokosumi, «агенты нанимают агентов». Минус: туннель и регистрация в день дедлайна.

### 4C. ✅ Aiken-валидатор, проверяющий подпись Airnode на Cardano — 23 теста зелёные, `onchain/plutus.json`
Главный козырь: «any contract can verify», включая Cardano-контракт.
- Plutus V3 builtins: `keccak_256` + `verifyEcdsaSecp256k1Signature`.
- Сообщение: `keccak256("\x19Ethereum Signed Message:\n32" ‖ keccak256(requestHash ‖ uint256(timestamp) ‖ data))`.
- ECDSA без recover: сжатый pubkey Airnode — параметр валидатора (извлечь офлайн из известной подписи через viem).
- Подпись: 64 байта (r‖s), low-s; `v` отбросить.
- Тест: `aiken check` на фикстуре IB1314 + 4 подделки (edit / wrong request / wrong signer / stale) — зеркало tamper lab из EVM.
- Дальше: спенд-валидатор «пул выплат», который отдаёт ADA холдеру при `status == Canceled` или задержке ≥ N мин.
- Gate: если к 12:30 `aiken check` не зелёный, остановить и оставить как «real-use path».

**Ответы судьям (заготовка):**
- *Почему Cardano?* Нативная оплата за запрос без аккаунтов; facilitator не держит ключей; UTxO-nonce даёт защиту от replay; дешёвые комиссии.
